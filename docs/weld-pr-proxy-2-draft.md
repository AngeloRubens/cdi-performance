**Title:** WELD-XXXX Cheaper interception context for intercepted subclasses and client proxies

## Summary

1. **Reuse a per-thread `InterceptionDecorationContext` stack.** Every invocation of a method of an intercepted
   subclass (intercepted *and* non-intercepted methods push the subclass handler) allocated a `Stack` and an
   `ArrayDeque` outside of a request, set the thread-local and cleared it again when the stack became empty. The
   thread-local now holds a small `Object[]` holder (a JDK class) that references the per-thread stack strongly
   only while it is non-empty and through a `WeakReference` otherwise. An idle thread never retains a Weld class
   (no class loader leak) and the stack is reused until a GC clears the weak reference. The `RequestScopedCache`
   registration of the stack (WELD-1812) and its validity tracking are no longer needed.
2. **Skip the thread-local lookup in client proxies until an interception context has ever been used.**
   `startIfNotEmpty()` invokes a constant `MethodHandle` guarded by a `SwitchPoint`: it returns `null` without any
   lookup until the first per-thread stack holder is created, at which point the switch point is invalidated
   (once per class loader, before the holder is published to the creating thread). A thread can only have an
   active stack if it created its holder itself, so the result is identical to the old code. The JIT folds the
   guard: deployments without interceptors/decorators skip the `ThreadLocal.get()`, deployments using interception
   pay nothing extra. (A plain `static boolean` was tried first and cost ~8 % on client proxy calls once
   interception had been used, see below.)
3. **`ContextBeanInstance` keeps the bean as `RIBean`** and goes straight to its `ContextualInstanceStrategy`
   (for `@ApplicationScoped` a volatile read of the cached instance) without the `instanceof` dispatch in
   `ContextualInstance`. Invalidation is unchanged; the strategy remains the only cache.

No generated bytecode changes; no observable behaviour change.
